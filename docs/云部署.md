# QuantumLink IM 云部署指南（开盖即食版）

> 本文面向"把 QuantumLink 部署到一台 Linux 云服务器"这一件事。照着顺序执行即可跑通，
> 也可以直接丢给 AI 让它按本文一步步操作。默认单机部署（中间件 Docker 容器 + 应用宿主机进程）。

---

## 0. 架构与端口总览

```
宿主机(Linux)
 ├─ Docker 容器(中间件):
 │   ├─ MySQL        127.0.0.1:3306   库 quantumlink
 │   ├─ Redis        127.0.0.1:6379
 │   ├─ RocketMQ     127.0.0.1:9876(namesrv) / 10911(broker)
 │   ├─ Nacos        127.0.0.1:8848(HTTP) / 9848(gRPC)
 │   └─ MinIO        127.0.0.1:9000(API) / 9001(控制台)  [可选]
 └─ 应用进程(java -jar):
     ├─ im-chat      8081(Spring Boot 业务层)
     └─ im-connect   19001 / 19002(Netty 长连接层)
```

应用全部通过 `127.0.0.1` 连中间件。**唯一必须覆盖的环境变量是 Nacos 地址**（代码默认 8850，
但标准 Nacos 是 8848，见第 5 节）。

## 1. 前置：系统环境

```bash
# 1.1 确认 Linux + 内核(任意主流发行版即可:Ubuntu 20.04+/CentOS 7+/Debian)
uname -a

# 1.2 安装 JDK 17(应用进程需要;Docker 中间件不需要)
# Ubuntu/Debian:
sudo apt-get update && sudo apt-get install -y openjdk-17-jdk-headless
# CentOS:
sudo yum install -y java-17-openjdk-headless

java -version   # 确认是 17

# 1.3 安装 Docker + Docker Compose(装中间件用)
curl -fsSL https://get.docker.com | sh
sudo systemctl enable --now docker
docker compose version   # 确认可用

# 1.4 系统参数(长连接必需,否则万级连接会因文件描述符耗尽失败)
sudo sysctl -w net.core.somaxconn=1024
ulimit -n 65535          # 当前 shell 生效;持久化写进 /etc/security/limits.conf
```

> **安全组/防火墙**：云服务器控制台需放行端口 8081、19001、19002（应用对外），
> 中间件端口 3306/6379/9876/10911/8848/9000 只需本机访问，不必对公网开放。

## 2. 获取代码并构建 jar

两种方式二选一：

**方式 A：云上直接构建（需要 Maven，最简单）**
```bash
# 2.1 装 Maven
sudo apt-get install -y maven

# 2.2 拉代码
git clone git@github.com:JDX473/QuantumLink.git && cd QuantumLink
git checkout dev

# 2.3 构建(跳过测试)
mvn clean package -DskipTests
# 产物:
#   im-chat/target/im-chat-1.0.0-SNAPSHOT.jar
#   im-connect/target/im-connect-1.0.0-SNAPSHOT.jar
```

**方式 B：本地打包上传（本地已配好 JDK17 时）**
```bash
# 本地(Windows)执行:
#   JAVA_HOME="D:\\jdk17" mvn clean package -DskipTests
# 然后把整个项目目录(或至少 im-chat/target、im-connect/target、sql、scripts)上传到云服务器,
# 保持目录结构不变(必须保留 im-chat/target/xxx.jar 这样的相对路径)。
```

构建完成后，确认项目根目录下有：
```
im-chat/target/im-chat-1.0.0-SNAPSHOT.jar
im-connect/target/im-connect-1.0.0-SNAPSHOT.jar
sql/schema.sql
scripts/start-all.sh
scripts/stop-all.sh
```

## 3. 启动中间件（Docker Compose）

在项目根目录创建两个文件：

**3.1 `docker-compose.yml`**（内容如下，直接复制）：
```yaml
version: "3.8"
services:
  mysql:
    image: mysql:8.0
    container_name: ql-mysql
    environment:
      MYSQL_ROOT_PASSWORD: "123456"
      MYSQL_DATABASE: quantumlink
    command: --character-set-server=utf8mb4 --collation-server=utf8mb4_unicode_ci
    ports:
      - "3306:3306"
    volumes:
      - ./sql/schema.sql:/docker-entrypoint-initdb.d/schema.sql
      - mysql-data:/var/lib/mysql

  redis:
    image: redis:7
    container_name: ql-redis
    command: redis-server --requirepass ""   # 不设密码;要设密码改成 --requirepass 你的密码,并同步第 5 节 IM_REDIS_PASSWORD
    ports:
      - "6379:6379"
    volumes:
      - redis-data:/data

  rocketmq-namesrv:
    image: apache/rocketmq:5.3.1
    container_name: ql-namesrv
    command: sh mqnamesrv
    ports:
      - "9876:9876"

  rocketmq-broker:
    image: apache/rocketmq:5.3.1
    container_name: ql-broker
    depends_on:
      - rocketmq-namesrv
    command: sh mqbroker -n rocketmq-namesrv:9876 -c /home/rocketmq/broker.conf
    ports:
      - "10911:10911"
    volumes:
      - ./broker.conf:/home/rocketmq/broker.conf

  nacos:
    image: nacos/nacos-server:v2.5.0
    container_name: ql-nacos
    environment:
      MODE: standalone
    ports:
      - "8848:8848"
      - "9848:9848"

  minio:
    image: minio/minio:latest
    container_name: ql-minio
    environment:
      MINIO_ROOT_USER: minioadmin
      MINIO_ROOT_PASSWORD: minioadmin
    command: server /data --console-address ":9001"
    ports:
      - "9000:9000"
      - "9001:9001"
    volumes:
      - minio-data:/data

volumes:
  mysql-data:
  redis-data:
  minio-data:
```

**3.2 `broker.conf`**（RocketMQ broker 配置，固定 brokerIP1 为 127.0.0.1，防止云主机多网卡时注册错 IP）：
```
brokerClusterName = DefaultCluster
brokerName = broker-a
brokerId = 0
deleteWhen = 04
fileReservedTime = 48
brokerRole = ASYNC_MASTER
flushDiskType = ASYNC_FLUSH
brokerIP1 = 127.0.0.1
```

**3.3 启动**：
```bash
docker compose up -d
# 等待约 30~60s(MySQL 首启初始化 schema、RocketMQ broker 注册)
docker compose ps   # 确认 6 个容器都是 Up
```

**3.4 验证中间件就绪**（全部能连上即可）：
```bash
docker exec ql-mysql mysql -uroot -p123456 -e "show databases;" | grep quantumlink
docker exec ql-redis redis-cli ping          # 应返回 PONG
docker exec ql-namesrv sh -c "netstat -ltn | grep 9876"   # 可选
docker exec ql-broker sh -c "netstat -ltn | grep 10911"   # 可选
curl -s http://127.0.0.1:8848/nacos/         # Nacos 控制台应返回页面
curl -s http://127.0.0.1:9000/minio/health/live   # MinIO 健康检查(可选)
```

## 4. 数据库初始化

MySQL 容器首次启动时，`sql/schema.sql` 已通过挂载到 `/docker-entrypoint-initdb.d/` **自动执行**（建库建表 + 种子用户）。

docker exec -i ql-mysql mysql -uroot -p123456 quantumlink < sql/schema.sql

## 5. 配置环境变量（关键一步）

```bash
# 在启动应用的 shell 里 export 以下变量(也可写进 ~/.bashrc 或启动脚本)
# 默认值已适配"单机 Docker 中间件",大多数不用改;必须改的是 Nacos 地址。

# 5.1 Nacos(必改:代码默认 8850 是 Windows 偏移值,标准 Nacos 是 8848)
export IM_NACOS_ADDR=127.0.0.1:8848

# 5.2 以下按需改(不设则用默认,默认恰好是上面的 Docker 端口):
# export IM_MYSQL_HOST=127.0.0.1
# export IM_MYSQL_PORT=3306
# export IM_MYSQL_DB=quantumlink
# export IM_MYSQL_USER=root
# export IM_MYSQL_PASSWORD=123456
# export IM_REDIS_HOST=127.0.0.1
# export IM_REDIS_PORT=6379
# export IM_REDIS_PASSWORD=          # Redis 设了密码就填
# export IM_ROCKETMQ_NAMESRV=127.0.0.1:9876
# export IM_MINIO_ENDPOINT=http://127.0.0.1:9000
# export IM_MINIO_ACCESS_KEY=minioadmin
# export IM_MINIO_SECRET_KEY=minioadmin
# export IM_MINIO_BUCKET=avatar
# export IM_CONNECT_PORTS="19001 19002"   # 启动几个 connect 节点
```

> **Redis 设密码时**：同时改第 3.1 步 compose 里的 `--requirepass 你的密码` 和这里的 `IM_REDIS_PASSWORD`，两边一致。

## 6. 启动服务

```bash
cd QuantumLink
bash scripts/start-all.sh
```

脚本会：
1. 检查 6 个中间件端口是否就绪（未就绪的会打印 `[!!]` 提示，但不阻塞）
2. 用 nohup 启动 im-chat（8081）+ im-connect × N（默认 19001/19002）
3. 日志写到 `logs/im-chat.log`、`logs/im-connect-{port}.log`

**停止**：
```bash
bash scripts/stop-all.sh
```

# 7.2 chat 健康(调度接口,需要先有 token;直接访问应返回 JSON 而非拒绝连接)

## 8. 常见问题排查

| 现象 | 原因 | 解决 |
|---|---|---|
| chat 启动失败，日志报 `MinIO bucket init failed` | 见 AvatarStorageService：已改为**可降级**，仅告警不阻断，头像功能不可用但服务正常起 | 忽略，或启动 MinIO |
| 客户端报 `connect to <旧IP>:10911 failed` | RocketMQ broker 注册了错误网卡 IP | 确认 broker.conf 的 `brokerIP1=127.0.0.1`，重启 broker 容器 `docker compose restart rocketmq-broker` |
| 调度接口返回空节点 | Nacos 地址不对（代码默认 8850，标准是 8848） | 确认 `export IM_NACOS_ADDR=127.0.0.1:8848`，且 connect 日志里 nacos 连接成功 |
| 万级连接连不上 / 报 too many open files | 文件描述符限制 | `ulimit -n 65535` 并持久化到 `/etc/security/limits.conf` |
| 端口冲突 | 8081/19001 等被占 | `ss -ltnp` 排查，改 `IM_CHAT_PORT`/`IM_CONNECT_PORTS` |
| 中间件没起 | Docker 未启动/镜像拉取失败 | `docker compose ps` 看状态，`docker compose logs -f 容器名` 看日志 |

## 9. 生产加固提醒（压测/正式环境前）

- **Redis 设密码**：云上 Redis 默认无密码有风险，建议 `--requirepass` + `IM_REDIS_PASSWORD`
- **MySQL 改强密码**：compose 里的 `123456` 改成强密码，同步 `IM_MYSQL_PASSWORD`
- **Nacos 鉴权**：正式环境开启 Nacos 账号密码（本文 standalone 未开启）
- **连接数上限**：本项目尚未实测万级连接上限，生产前建议用云环境做一次连接数压测（这是当前唯一未做的验证项）
