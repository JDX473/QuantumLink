# QuantumLink IM 云部署指南（开盖即食版 · 原生安装）

> 本文面向"把 QuantumLink 部署到一台 Linux 云服务器"这一件事。中间件与项目现状一致：
> **全部原生安装（不用 Docker）**。照着顺序执行即可跑通，也可以直接丢给 AI 让它按本文操作。
> 默认单机部署：中间件 + 应用全在同一台服务器。

---

## 0. 架构与端口总览

```
一台 Linux 服务器
 ├─ 中间件(原生进程):
 │   ├─ MySQL    127.0.0.1:3306   库 quantumlink
 │   ├─ Redis    127.0.0.1:6379
 │   ├─ RocketMQ 127.0.0.1:9876(namesrv) / 10911(broker)
 │   ├─ Nacos    127.0.0.1:8848
 │   └─ MinIO    127.0.0.1:9000   [可选,头像功能才需要]
 └─ 应用(java -jar):
     ├─ im-chat      8081(业务层)
     └─ im-connect   19001 / 19002(长连接层)
```

应用通过 `127.0.0.1` 连中间件。**唯一必须覆盖的环境变量是 Nacos 地址**（代码默认 8850，标准 Nacos 是 8848，见第 5 节）。

---

## 1. 前置：系统环境

```bash
# 1.1 Linux 系统(主流发行版均可:Ubuntu 20.04+/Debian/CentOS 7+)
uname -a

# 1.2 安装 JDK 17(应用 + RocketMQ/Nacos 都需要 Java)
# Ubuntu/Debian:
sudo apt-get update && sudo apt-get install -y openjdk-17-jdk-headless
# CentOS:
sudo yum install -y java-17-openjdk-headless

java -version   # 确认 17

# 1.3 系统参数(长连接必需,否则万级连接因文件描述符耗尽失败)
sudo sysctl -w net.core.somaxconn=1024
ulimit -n 65535          # 当前 shell 生效;持久化写 /etc/security/limits.conf
```

> **安全组/防火墙**：云控制台放行 8081、19001、19002（应用对外）；中间件端口只需本机访问，不必对公网开。

## 2. 获取代码并构建 jar

两种方式二选一：

**方式 A：云上直接构建（需要 Maven）**
```bash
sudo apt-get install -y maven
git clone git@github.com:JDX473/QuantumLink.git && cd QuantumLink
git checkout dev
mvn clean package -DskipTests
# 产物:
#   im-chat/target/im-chat-1.0.0-SNAPSHOT.jar
#   im-connect/target/im-connect-1.0.0-SNAPSHOT.jar
```

**方式 B：本地打包上传**
本地 `mvn clean package -DskipTests` 后，把项目目录（至少 `im-chat/target`、`im-connect/target`、`sql`、`scripts`）上传到云服务器，**保持目录结构不变**（start-all.sh 依赖 `im-chat/target/xxx.jar` 相对路径）。

## 3. 安装中间件（原生）

> **一键安装**（Ubuntu/Debian）：`bash scripts/install-middleware.sh` 会自动装 JDK17 + MySQL + Redis + RocketMQ + Nacos + MinIO 并启动、配好 brokerIP1/JVM 堆/资源参数。下面 3.1~3.5 是各中间件的**手动步骤**（脚本失败或非 Ubuntu 发行版时用）。

### 3.1 MySQL 8

```bash
# Ubuntu/Debian
sudo apt-get install -y mysql-server
sudo systemctl enable --now mysql
# CentOS
sudo yum install -y mysql-server && sudo systemctl enable --now mysqld

# 设置 root 密码为 123456(与第 5 节 IM_MYSQL_PASSWORD 一致)
sudo mysql -e "ALTER USER 'root'@'localhost' IDENTIFIED WITH mysql_native_password BY '123456'; FLUSH PRIVILEGES;"

# 建库建表(执行项目 schema.sql)
mysql -uroot -p123456 < sql/schema.sql
```

### 3.2 Redis

```bash
sudo apt-get install -y redis-server      # CentOS: sudo yum install -y redis
# 确认只监听本机(云上不要暴露公网)
sudo sed -i 's/^bind .*/bind 127.0.0.1/' /etc/redis/redis.conf
# 建议设密码(可选,设了要同步第 5 节 IM_REDIS_PASSWORD):
# sudo sed -i 's/^# requirepass .*/requirepass 你的密码/' /etc/redis/redis.conf
sudo systemctl enable --now redis-server
redis-cli ping    # 返回 PONG
```

### 3.3 RocketMQ 5.3.1

```bash
cd /opt
sudo wget https://dist.apache.org/repos/dist/release/rocketmq/5.3.1/rocketmq-all-5.3.1-bin-release.zip
sudo unzip rocketmq-all-5.3.1-bin-release.zip
cd rocketmq-all-5.3.1-bin-release

# 关键①:改 broker 注册地址(云主机多网卡会注册错 IP,固定 127.0.0.1)
cat > conf/broker-local.conf <<'EOF'
brokerClusterName = DefaultCluster
brokerName = broker-a
brokerId = 0
deleteWhen = 04
fileReservedTime = 48
brokerRole = ASYNC_MASTER
flushDiskType = ASYNC_FLUSH
brokerIP1 = 127.0.0.1
EOF

# 关键②:RocketMQ 启动脚本默认 JVM 堆 4g/8g,小内存服务器会启动失败,先改小
sed -i 's/-Xms4g/-Xms256m/; s/-Xmx4g/-Xmx512m/' bin/runserver.sh     # namesrv
sed -i 's/-Xms8g/-Xms256m/; s/-Xmx8g/-Xmx512m/' bin/runbroker.sh     # broker

# 启动 namesrv + broker(需 JAVA_HOME 指向 JDK)
export JAVA_HOME=$(dirname $(dirname $(readlink -f $(which java))))
nohup sh bin/mqnamesrv > namesrv.log 2>&1 &
sleep 5
nohup sh bin/mqbroker -n 127.0.0.1:9876 -c conf/broker-local.conf > broker.log 2>&1 &
sleep 20

# 验证
ss -ltn | grep -E "9876|10911"
```

> RocketMQ 5.3.1 官方要求 JDK 8 或 11；JDK 17 一般也能跑，若启动报 JVM 相关错误，单独装 openjdk-8-jdk 并让 RocketMQ 用 JDK8 启动。

### 3.4 Nacos 2.5.0

```bash
cd /opt
sudo wget https://github.com/alibaba/nacos/releases/download/2.5.0/nacos-server-2.5.0.tar.gz
sudo tar -xzf nacos-server-2.5.0.tar.gz
cd nacos
export JAVA_HOME=$(dirname $(dirname $(readlink -f $(which java))))
sh bin/startup.sh -m standalone    # 默认监听 8848
sleep 20

# 验证(应返回 Nacos 页面 JSON)
curl -s http://127.0.0.1:8848/nacos/
```

### 3.5 MinIO（可选，头像功能才需要；不装 chat 也能启动）

```bash
sudo mkdir -p /data/minio && cd /usr/local/bin
sudo wget https://dl.min.io/server/minio/release/linux-amd64/minio
sudo chmod +x minio
MINIO_ROOT_USER=minioadmin MINIO_ROOT_PASSWORD=minioadmin \
  nohup minio server /data/minio --address ":9000" --console-address ":9001" > /data/minio/minio.log 2>&1 &
curl -s http://127.0.0.1:9000/minio/health/live   # 应返回 {}
```

## 5. 配置环境变量（关键一步）

```bash
# 在启动应用的 shell 里 export(或写进 ~/.bashrc / 启动脚本)
# 默认值已适配"单机 + 上述端口",大多数不用改;必须改的是 Nacos 地址。

export IM_NACOS_ADDR=127.0.0.1:8848     # 必改:代码默认 8850 是 Windows 偏移值,标准 Nacos 是 8848
export IM_CONNECT_HOST=公网IP            # 必改:connect 对外地址(节点注册 Nacos + 调度接口返回给客户端)。
                                         # 不设则返回 127.0.0.1,远程客户端连不上;填服务器公网/内网 IP

# 以下按需改(不设则用默认,默认恰好是上面装的端口):
# export IM_CHAT_PORTS="8081 8082"      # chat 实例数,默认双实例分摊 CPU(8C 建议保持双实例)
# export IM_MYSQL_HOST=127.0.0.1
# export IM_MYSQL_PORT=3306
# export IM_MYSQL_DB=quantumlink
# export IM_MYSQL_USER=root
# export IM_MYSQL_PASSWORD=123456
# export IM_REDIS_HOST=127.0.0.1
# export IM_REDIS_PORT=6379
# export IM_REDIS_PASSWORD=          # Redis 设了密码就填
# export IM_ROCKETMQ_NAMESRV=127.0.0.1:9876
# export IM_MINIO_ENDPOINT=http://127.0.0.1:9000
# export IM_MINIO_ACCESS_KEY=minioadmin
# export IM_MINIO_SECRET_KEY=minioadmin
# export IM_MINIO_BUCKET=avatar
# export IM_CONNECT_PORTS="19001 19002"   # 启动几个 connect 节点
```

**客户端侧（压测/桌面端在另一台电脑）**：连接目标同样用环境变量指到服务器——`IM_CONNECT_HOST=服务器IP`（验证脚本 TCP 连接目标）、`IM_API=http://服务器IP:8081`（业务 HTTP 接口）。同时**安全组/防火墙必须对客户端放行 8081、19001、19002**。验证注册结果：`curl http://127.0.0.1:8081/api/connects`（带 token）应返回 `IM_CONNECT_HOST` 指定的地址。

## 6. 启动服务

```bash
cd QuantumLink
bash scripts/start-all.sh
```

脚本会：检查 6 个中间件端口 → nohup 启动 im-chat × N（默认 8081/8082 双实例）+ im-connect × N → 日志写 `logs/`（chat 按端口分文件 `im-chat-8081.log` 等）。

**停止**：
```bash
bash scripts/stop-all.sh
```

## 8. 常见问题排查

| 现象 | 原因 | 解决 |
|---|---|---|
| chat 日志报 `MinIO bucket init failed` | 已改为可降级：仅告警不阻断启动，头像不可用 | 忽略，或启动 MinIO |
| 客户端报 `connect to <旧IP>:10911 failed` | RocketMQ broker 注册了错误网卡 IP | 确认 `broker-local.conf` 的 `brokerIP1=127.0.0.1`，重启 broker |
| RocketMQ 启动失败 / 内存不足 | runbroker.sh 默认 JVM 8g | 已按 3.3 改成 512m；若还失败确认 JAVA_HOME |
| 调度接口返回空节点 | Nacos 地址不对（默认 8850 vs 标准 8848） | `export IM_NACOS_ADDR=127.0.0.1:8848` |
| 远程客户端连不上 / 调度返回 127.0.0.1 | connect 的 nodeId 用了默认 127.0.0.1 | `export IM_CONNECT_HOST=公网IP` 后重启 connect |
| 万级连接报 too many open files | 文件描述符限制 | `ulimit -n 65535` 并持久化 |
| 端口冲突 | 8081/19001 被占 | `ss -ltnp` 排查，改 `IM_CHAT_PORTS`/`IM_CONNECT_PORTS` |

## 9. 8C16G 资源参数配置（推荐）

8C16G 单机全塞时，把中间件默认参数调到位（默认值不是太小就是太大）：

### MySQL（innodb_buffer_pool 默认 128M 太小）
```bash
sudo tee -a /etc/mysql/mysql.conf.d/mysqld.cnf <<'EOF'
[mysqld]
innodb_buffer_pool_size = 2G
EOF
sudo systemctl restart mysql
```

### Redis（maxmemory 防 dedup key 膨胀 OOM）
```bash
sudo tee -a /etc/redis/redis.conf <<'EOF'
maxmemory 1gb
maxmemory-policy allkeys-lru
EOF
sudo systemctl restart redis-server
```

### JVM 堆
start-all.sh 已内置：im-chat `-Xmx1g`、im-connect `-Xmx512m`，无需手动调。

### CPU 分配（不用绑核，但要理解谁吃核）
- **im-chat × 2（8081/8082）是唯一 CPU 瓶颈**（压测实测单实例 60 连接就 57% 饱和），
  双实例经 RocketMQ 同 group 自动分摊队列，吃掉 4-6 核
- im-connect × 2（19001/19002）IO 密集、CPU 轻
- Redis 单线程占 1 核，MySQL/RocketMQ 中低负载
