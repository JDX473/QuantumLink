# 多端踢人:同端单设备 + 手动踢设备

> 一句话结论:**同端类型单设备模式 + 手动踢设备。KICK 用 Redis Pub/Sub(`im:kick` 频道):chat 发布 {userId, deviceId},所有 connect 节点订阅、本地判目标关连接;配合"删 token 使重连被拒"兜底。**(2026-08-09)

## 为什么要踢

多端并存(2026-08-08)后,同账号多设备同时在线。产品需要两种踢人:
1. **同端单设备**:桌面/移动各留一台,新登录自动踢同类型的旧设备
2. **手动踢**:用户在设备管理里手动踢掉某台设备

## KICK 设计:Redis Pub/Sub,不是 MQ

**为什么走 Pub/Sub 不走 MQ**:KICK 是低频、尽力而为的控制消息——
- Pub/Sub 天然**广播**(无消费者组概念,每个订阅者都收到),符合"全节点都要知道"
- 即发即弃的缺点被"删 token 使重连被拒"兜底(踢不到也出局)
- 不用查会话表定位节点,广播出去让持有者自己认领

**广播 + 本地判目标**:所有 connect 节点订阅 `im:kick` 都收到指令,但只有 `ChannelManager.get(userId, deviceId) != null`(持有目标连接)的节点才关,其余忽略——不加判断直接关,广播会误杀所有节点的同 userId 连接。

## 踢人四步(chat 端发起)

```
① 删 token(im:token:{token})           ← 踢死根基,重连握手必然失败
② publish KICK 到 Redis Pub/Sub im:kick ← {userId, deviceId}
③ connect KickSubscriber 收到 → 本地判目标
   → 目标 EventLoop 上:主动删 Redis 路由表(sessionRegistry.remove)
   → 删本地 ChannelManager → closeWithRetry    ← 与连接 I/O 不交错,消除竞态
④ close 异步完成,回调里 isActive() 判断:还活着 → 重试一次
```

**解耦关键(2026-08-09 改进)**:删 Redis 路由表**不依赖 close 成功**——原实现靠 close 触发 onDisconnect 才删(close 失败则 onDisconnect 不跑、路由表残留,死连接靠心跳 getNode 查得到续命,兜不住)。现在踢人时**主动先删** `sessionRegistry`(Redis 路由表)+ `ChannelManager`(本地),最后 close;close 失败(isActive)重试一次,仍失败由**心跳兜底**:路由表已删 → 心跳续期前 getNode=null → 关连接。**踢人不会留下永续死连接。**

## 两种触发

| 触发 | 入口 | 逻辑 |
|---|---|---|
| **同端踢人** | 登录时 `AuthService.kickSameTypeDevices(userId, deviceType, excludeDeviceId)` | 踢同 deviceType 的旧设备,排除正在登录的设备 |
| **手动踢** | `POST /api/auth/devices/{deviceId}/kick` | `AuthService.kickDevice`:删 token + publish KICK,只能踢自己的设备 |

## 心跳修复(配套)

HeartbeatHandler 续期前查会话表 `sessionRegistry.getNode`,路由表没了(被踢)→ **拒续期 + 关连接**——否则被踢的死连接靠心跳续命,TTL 兜底失效。

## 踩坑

- **close 失败重试**:close 是异步的,回调里判断 `isActive()`,仍活着重试一次;重试耗尽告警并靠心跳兜底(路由表已前置删 → 心跳 getNode=null → 关连接)——踢人不会留下永续死连接
- **KickSubscriber 不能在 close 前 clear ConnectionContext**:否则 close 触发 channelInactive → onDisconnect 时 userId 已是 null,提前返回,清理失效(路由表虽已主动删,仍保语义干净)
- **只关连接不够**:客户端会自动重连,若 token 还有效会重新进来(白踢)——必须同时删 token 让重连失败,"关连接 + 删 token"两个动作一起
- **清理必须在目标 EventLoop 线程**:与连接 I/O 不交错,消除竞态

## 验证

`scripts/verify-kick.js`:① 同端 mobile 新登录踢旧——A 断开、设备列表 A 离线 / B 在线;② 设备踢除端点踢 B——B 断开、离线。139 单测全过。

## 面试要点

- **为什么 Pub/Sub 不做 MQ**:广播语义天然契合"全节点都收到";即发即弃可接受(删 token 兜底)
- **为什么本地判目标**:广播所有节点都收到,不加判断会误杀所有节点的同 userId 连接
- **为什么在 EventLoop 上 close**:与连接 I/O 不交错,消除竞态;先 remove map 再 close 避免新下行找到它
- **为什么"删 token + KICK"缺一不可**:只关连接客户端会重连回来(白踢),只删 token 挡不住已建连接——两个动作一起才完整
